# Exploratory authentic-application gate — 19 October 2026

This plan is recorded after the synthetic prototype and focused priority check,
before the parent accepts or executes a real-data source-mode case. Candidate
discovery is exploratory, not preregistered, blinded, independent deployment or
an exhaustive search. Failure to find a suitable application is a valid outcome.

## Admission criteria

- Obtain numbers and definitions from inspectable primary public sources, with
  exact URLs, release/version dates, locators and extraction route. Record missing
  access rather than substituting an unverified transcription.
- Fix entity/cohort, reporting window, units, membership and query before running
  the certainty solver. Use a meaningful externally motivated comparison; do not
  tune a margin or threshold until a desired result appears.
- Explain each whole-source mode and why its values belong together. Published
  revisions may support bounded release-vintage robustness, not a claim that a
  superseded and a corrected release are equally valid current truths. Public
  availability and hashes alone do not authenticate underlying measurements.
- Never call independently produced perturbations observed source ambiguity.
  Consolidated and separate accounts, mismatched windows, different price-return
  definitions or unrelated entities are not interchangeable modes.
- Admit only the implemented common-centre strict-comparison fragment, with
  locally qualified values and logically independent source groups. Preserve
  genuine dependencies by grouping them together, or reject the case. A single
  coherent publication group is valid but cannot demonstrate multi-group scale.
- State whether the finite modes exhaust a documented set or are only selected
  alternatives. Certainty is conditional on this set and the qualification rules.

## Execution if a case is admitted

Preserve source transcriptions separately from the solver input and record every
derivation with exact rational arithmetic. Compare the interval answer with the
independent original-role-binding world oracle and exact SAT baseline, including
all compilation in SAT totals. Independently check the execution certificate or
counterworld. Run the incomplete marginal-envelope bound as a secondary control;
do not force it to fail or infer general system incapability from its answer.
Record input/output hashes, all cases tried, disagreement or rejection, missing
roles and the original mode IDs. Do not treat an exception/resource limit as a
negative or certain result. Large possible-world products are theoretical counts,
not observed timeouts or empirical samples. Small real cases provide usefulness
evidence, not a competitive scaling experiment.

## Integration gate

A provenance-linked real-data replay may support a disclosed optional component.
It does not by itself establish a novel algorithm, practitioner benefit, an
independent deployment or journal acceptance. The interval sweep is standard,
and existing provenance systems can express correlated aggregate comparisons.
Do not recast the manuscript around this prototype unless the actual task and
results warrant it. If no suitable case is admitted, retain the prototype and
write the reason; do not manufacture uncertainty or request participants merely
to make this gate pass.
